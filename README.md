# DocuQuery — Evidence-Based Research Workspace

DocuQuery is a full-stack document research application. It ingests text-based PDFs, retrieves relevant passages from a document-specific vector collection, and generates answers grounded in those passages. The frontend also includes tools to inspect retrieval results and compare search settings.

## Architecture

```text
React + TypeScript (Vite)
        │  session cookie (dq_sid)
        ▼
Node.js + Express API ───── In-memory document metadata and sessions
        │  X-Internal-Token (loopback only)
        ▼
Python + FastAPI ────────── Local Qdrant (document chunks and vectors)
        │
        ├── Sentence Transformers: all-MiniLM-L6-v2 (384 dimensions)
        └── Groq API (answer generation)
```

The browser calls the Node API. Node owns visitor sessions, document ownership, and deletion sequencing, then proxies search, ingest, answer, and deletion requests to FastAPI. The Python service requires an internal token and should only be reachable from Node on loopback.

## Privacy and access model

- Each browser receives an HttpOnly, SameSite=Lax session cookie (`dq_sid`). The server derives an owner ID from that session; clients cannot choose or override ownership.
- Uploaded documents are private to the session that uploaded them. Uploaded document IDs are generated by the server. Other sessions receive a non-disclosing `404` for listing, metadata, search, answer, or deletion attempts.
- The bundled `python-service/rag-content.pdf` is a shared, public, read-only sample. It is visible to every session and cannot be deleted.
- The frontend must call the API with credentials included. `frontend/src/api/client.ts` does this for every request.
- The Python service is not a public API. Every sensitive Python route requires `X-Internal-Token`, and the token is never sent to the browser.
- State-changing requests require a trusted `Origin`/`Referer`; CORS allows only the origins in `FRONTEND_ORIGIN`.
- Answers are generated through Groq. The question and retrieved document context are sent to Groq for answer generation. Do not upload sensitive documents unless that processing is acceptable for your use case.
- This project has no user accounts. Clearing cookies or using another browser creates a new session that cannot access the old session's documents. Sessions and metadata are process-local and are lost on restart.

## Requirements

- Node.js with npm
- Python and the Python service's dependencies (including FastAPI, Qdrant Client, Sentence Transformers, Groq, `pypdf`, `python-multipart`, and PyMuPDF)
- Tesseract with English language data if OCR is needed for scanned pages
- A Groq API key for answer generation

The Python service currently has no checked-in `requirements.txt` or `pyproject.toml`; install its dependencies in a virtual environment before starting it.

## Local setup

### 1. Configure environment

Copy the relevant example files to `.env` and provide local values:

- Root `.env.example` is a combined reference for all three services.
- `frontend/.env.example` contains `VITE_API_URL`.
- `node-service/.env.example` contains the Node port, Python API URL, allowed frontend origins, session secret, and limits.
- `python-service/.env.example` contains `GROQ_API_KEY`, the internal token, and optional Qdrant storage overrides.
- Each service loads its own `.env` file (`node-service/.env`, `python-service/.env`, `frontend/.env`); the root example is not loaded automatically.
- `PYTHON_INTERNAL_TOKEN` must be the same value in `node-service/.env` and `python-service/.env` so Node can call Python.

For local development, both services fall back to a development internal token and Node falls back to an ephemeral session secret. Those fallbacks are not suitable for production. In production, set `NODE_ENV=production` and `DOCUQUERY_ENV=production`, use a `SESSION_SECRET` of at least 32 characters, and use a `PYTHON_INTERNAL_TOKEN` of at least 16 characters.

Keep the frontend and API on the same hostname (for example, both `localhost`, not `localhost` and `127.0.0.1`). Otherwise the browser will not send the session cookie. Behind HTTPS, set `NODE_ENV=production` so the cookie is marked `Secure`, and serve the app over HTTPS.

Do not commit `.env` files or credentials.

### 2. Start the Python service

In a terminal:

```powershell
cd python-service
.\.venv\Scripts\Activate.ps1
uvicorn main:app --host 127.0.0.1 --port 8000
```

The service uses a local Qdrant data directory under `python-service/qdrant_storage` by default. Set `QDRANT_STORAGE_PATH` to override it. Bind it to loopback; it is protected by the internal token, not by user accounts.

### 3. Start the Node API

In another terminal:

```powershell
cd node-service
npm install
npm start
```

The API listens on `http://localhost:3000` by default. It stores session and document metadata in process memory.

### 4. Start the frontend

In another terminal:

```powershell
cd frontend
npm ci
npm run dev
```

The frontend uses `http://localhost:5173`; it will fail to start rather than silently switching ports if 5173 is occupied. Set `VITE_API_URL` in `frontend/.env` if the Node API uses a different URL. Configure `FRONTEND_ORIGIN` in `node-service/.env` to match the frontend origin exactly. It accepts a comma-separated list.

## Using the workspace

1. Upload a text-based PDF from Research or Documents. Uploaded documents belong to the current browser session.
2. The bundled public sample (`rag-content`) appears in every session and can be queried but not deleted.
3. Select a ready document; its ID is retained in the URL when navigating between workspace sections.
4. Ask a question in Research to receive an answer with source and chunk citations.
5. Use RAG Explorer to inspect retrieved text and understand the pipeline. The API does not expose raw embeddings or the exact prompt/context as intermediate results.
6. Use Playground to adjust Top-K and similarity threshold, or compare configurations.
7. Delete private documents from the library. Node asks Python/Qdrant to delete the chunks first; metadata is removed only after that succeeds. If cleanup fails, the document remains visible with an error and deletion can be retried.

Similarity scores are vector similarity measures, not probabilities or confidence estimates.

### Limits

- Uploads: PDFs only through the Node API, 10 MB per file.
- Text ingestion: 100,000 characters per request; the Python service also caps extracted document text at 500,000 characters.
- PDFs: up to 100 pages and 60 seconds of parsing per document, including OCR.
- Sessions: up to 10 uploaded documents and 6 ingestion attempts per 10 minutes by default.
- Answer/search requests are rate limited per session. JSON request bodies are limited to 1 MB.

## API endpoints

### Node API — default `http://localhost:3000`

Browser requests use the session cookie. State-changing requests (`POST`, `PUT`, `PATCH`, `DELETE`) must include a trusted `Origin` or `Referer`.

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/health` | Node status (no session required) |
| `GET` | `/health/python` | Python service health via Node |
| `POST` | `/ingest-file` | Ingest a PDF; the server generates the private document ID |
| `POST` | `/ingest` | Ingest text with `source` and `text`; the server generates the ID |
| `POST` | `/answer` | Generate a document-grounded answer |
| `POST` | `/search` | Retrieve chunks for a document and query |
| `GET` | `/documents` | List the public sample plus the session's private documents |
| `GET` | `/documents/:documentId` | Get one visible document's metadata |
| `DELETE` | `/documents/:documentId` | Delete an owned private document and its Qdrant chunks |

For `POST /ingest-file`, send a multipart form field named `file`. `/answer` accepts `question`, `document_id`, and optional `limit` / `score_threshold`. `/search` uses the same query fields and returns retrieved chunk payloads. Client-supplied document IDs and owner IDs are ignored.

### Python API — default `http://127.0.0.1:8000`

The FastAPI service exposes `/health`, `/search`, `/ingest`, `/ingest-file`, `GET`/`DELETE` `/documents/{document_id}`, and `/answer`. Every route except `/health` requires `X-Internal-Token`. The frontend accesses Python only through the Node gateway.

The Python suite covers internal-token checks, Qdrant document-scope filtering, deletion isolation/idempotency, and PDF page/time limits. The frontend suite covers the credentialed API client and formatting helpers.

## Limitations and deployment notes

- Uploaded PDFs must contain extractable text. OCR uses Tesseract when available; scanned or unusual PDFs may still fail or be slow, and are subject to the page/time limits.
- The Node service is designed for a single instance. Sessions, rate limits, and document ownership metadata are held in process memory. Multiple Node instances or a process restart will invalidate sessions and lose ownership metadata.
- After a Node restart, Qdrant chunks from previous sessions can be orphaned because their ownership metadata is gone. Plan operational cleanup or a persistent metadata store before relying on this in production.
- Expired sessions are swept periodically; their private documents are deleted from Qdrant first, with retry bookkeeping when cleanup fails while the process is still running.
- Qdrant storage is local to the Python service and requires persistent storage in deployments.
- No user accounts exist. Access control is session-based only; anyone with a session cookie can access that session's documents.
- Match `SESSION_SECRET` and `PYTHON_INTERNAL_TOKEN` requirements in production, keep Python bound to loopback, and serve both Node and the frontend over HTTPS.
- Retrieval settings are tuned per workspace and should be validated against your document library and use case.
- UI pipeline stages that the API does not return are explanatory; only returned answers and retrieved chunk payloads are presented as live results.
